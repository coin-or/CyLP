cylp.cy.CyCbcModel¶

class cylp.cy.CyCbcModel.CyCbcModel[source]¶

Interfaces CbcModel. To solve a first you create a cylp.cy.CyClpSimplex object either by reading it from an mps file using CyClpSimplex.readMps() or by using cylp modeling tool cylp.py.modeling.CyLPModel. Then you ask the object for a CyCbcModel which is capable solving MIPs using B&B

Usage

>>> import numpy as np
>>> from cylp.cy import CyCbcModel, CyClpSimplex
>>> from cylp.py.modeling.CyLPModel import CyLPModel, CyLPArray
>>> model = CyLPModel()
>>>
>>> x = model.addVariable('x', 3, isInt=True)
>>> y = model.addVariable('y', 2)
>>>
>>> A = np.array([[1., 2., 0],[1., 0, 1.]])
>>> B = np.array([[1., 0, 0], [0, 0, 1.]])
>>> D = np.array([[1., 2.],[0, 1]])
>>> a = CyLPArray([5, 2.5])
>>> b = CyLPArray([4.2, 3])
>>> x_u= CyLPArray([2., 3.5])
>>>
>>> model += A @ x <= a
>>> model += 2 <= B @ x + D @ y <= b
>>> model += y >= 0
>>> model += 1.1 <= x[1:3] <= x_u
>>>
>>> c = CyLPArray([1., -2., 3.])
>>> model.objective = c * x + 2 * y.sum()
>>>
>>> s = CyClpSimplex(model)
>>>
>>> cbcModel = s.getCbcModel()
>>>
>>> cbcModel.solve()
0
>>> print(cbcModel.status)
solution
>>> sol_x = cbcModel.primalVariableSolution['x']
>>>
>>> (abs(sol_x - np.array([0, 2, 2])) <= 10**-6).all()
True

addPythonCutGenerator(self, pythonCutGeneratorObject, howOften=1, name='', normal=True, atSolution=False, infeasible=False, howOftenInSub=-100, whatDepth=-1, whatDepthInSub=-1)[source]¶

Add a cut generator written in Python: an object whose generateCuts(si, cglTreeInfo) method returns a list of cuts. See cylp/py/mip/GomoryCutGenerator.py for an example. The other arguments are those of addCutGenerator().

The cuts must be in terms of the model’s variables, but Cbc calls generateCuts on the problem after its preprocessing, which can have fewer rows and columns. See issue 255.

If generateCuts raises an exception, Cbc finishes its search without calling it again, and solve() then raises the exception.

status[source]¶

The result of solve():

  • 'solution' if Cbc proved that its solution is optimal, or within allowableGap or allowableFractionGap of the optimum,

  • 'relaxation infeasible', 'relaxation abandoned' or 'problem proven infeasible',

  • otherwise, why Cbc stopped: 'stopped on gap', 'stopped on nodes', 'stopped on time', 'stopped on user event', 'stopped on solutions', 'linear relaxation unbounded', 'search completed' or 'unset'.
